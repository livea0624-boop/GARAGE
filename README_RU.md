# GARAGE — Cloudflare D1, защита API и безопасная синхронизация

Подготовлены:

- `public/index.html` — исходник GARAGE с облачной синхронизацией;
- `src/worker.js` — API `/api/state` для чтения и замены общей записи в D1;
- `schema.sql` — создание таблицы `app_state`;
- `wrangler.jsonc` — подключение базы `garage-db`.

## 1. Создать таблицу D1

В каталоге проекта выполнить:

```bash
npx wrangler d1 execute garage-db --remote --file=./schema.sql
```

## 2. Установить пароль защиты API

Используется отдельный Cloudflare Secret. Введите **тот же общий пароль**, который установлен для входа в GARAGE:

```bash
npx wrangler secret put GARAGE_API_PASSWORD
```

Команда попросит ввести пароль. Не добавляйте его в GitHub, `wrangler.jsonc` или HTML-файл.

## 3. Развернуть проект

```bash
npx wrangler deploy
```

## Как работает защита

- запросы `GET` и `PUT` к `/api/state` без правильного заголовка `X-Garage-Password` отклоняются;
- сайт автоматически берёт пароль из локального ключа входа `garageSitePassword` и отправляет его по HTTPS;
- при восстановлении резервной копии запись в общей D1-базе также защищена;
- если пароль входа в настройках сайта изменён, необходимо обновить Cloudflare Secret той же командой `npx wrangler secret put GARAGE_API_PASSWORD`, введя новый пароль.

## Безопасная синхронизация нескольких продавцов

- Сервер сохраняет данные только при совпадении версии записи: конкурирующее сохранение получает HTTP 409, а не перезаписывает другого продавца.
- GARAGE автоматически объединяет независимые изменения разных заказов, клиентов и продаж.
- Если оба продавца изменили один и тот же заказ или запись, синхронизация останавливается с предупреждением: можно скачать локальную копию и загрузить данные из облака, не потеряв её.
- При пропадании сети локальные изменения не стираются очередным опросом; повторное сохранение выполняется после восстановления связи. Перед закрытием страницы с несохранёнными данными появляется предупреждение.
- Выбранный продавец и раскладка интерфейса остаются индивидуальными для каждого устройства.

### Обновление существующей базы

В `schema.sql` добавлено поле `version`. Если база создана ранее, Worker добавляет его сам при первом авторизованном запросе `/api/state`: `ALTER TABLE app_state ADD COLUMN version INTEGER NOT NULL DEFAULT 1`.

Перед обновлением рекомендуется экспортировать резервную копию GARAGE. **Не удаляйте таблицы**: сохранённые заказы должны остаться без изменений.

### Проверка на двух устройствах

1. На разных устройствах одновременно изменить разные заказы — оба изменения должны сохраниться.
2. Изменить один и тот же заказ одновременно — второе сохранение должно показать предупреждение о конфликте.
3. Отключить интернет, сделать правку и подключиться снова — правка должна сохраниться после восстановления сети.

## Проверка после деплоя

1. Открыть сайт и проверить загрузку данных.
2. Добавить тестового клиента и убедиться, что он появляется в D1.
3. Открыть сайт на другом устройстве с тем же паролем.
4. Проверить восстановление тестовой резервной копии.
5. Убедиться, что прямой запрос к `/api/state` без пароля возвращает `401 Unauthorized`.

> Важно: пароль передаётся только по HTTPS. Не публикуйте его в исходниках и не отправляйте в чат.

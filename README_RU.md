# GARAGE

Приложение для клиентов, автомобилей, заказов, оплат, поставок и возвратов. Интерфейс находится в `public/index.html`, стили — в `public/css/`, браузерная логика — в `public/js/`, API Cloudflare Worker — в `src/worker.js`.

## Локальная разработка

Требуются Node.js >=22.13 и npm. Версия Wrangler зафиксирована в package-lock.json.

```bash
npm ci
npm run d1:init:local
npm run dev -- --local --ip 127.0.0.1 --port 8787
```

Локальная D1 хранится в игнорируемом каталоге .wrangler/state. Команда инициализации создаёт недостающие таблицы без очистки данных. Для локальной разработки аккаунт Cloudflare и секреты не требуются. При первом запуске интерфейс предложит создать два разных пароля: входа и опасных действий. Их хеши хранятся в D1; `GARAGE_API_PASSWORD` текущий Worker не использует.

В облачной среде с недоступным домашним каталогом перед командами можно задать:

```bash
export npm_config_cache=/workspace/.cache/npm
export XDG_CONFIG_HOME=/workspace/.cloud-onboarding/garage/config
export XDG_CACHE_HOME=/workspace/.cache
export WRANGLER_LOG_PATH=/workspace/.cloud-onboarding/garage/logs
export WRANGLER_SEND_METRICS=false
export CLOUDFLARE_CF_FETCH_ENABLED=false
```

Последняя переменная отключает только необязательную загрузку географических метаданных Request.cf, которые приложение не использует.

## Проверки

```bash
npm test
npm run test:ui
npm run test:integration
npx wrangler deploy --dry-run
```

`npm test` проверяет финансовые расчёты, импорт, слияние изменений, очередь сохранения и серверные права. Серверные тесты выполняют настоящий SQL на встроенной SQLite без обращения к Cloudflare.

Браузерные проверки требуют Python 3, Playwright и Chromium. В подготовленной облачной среде они установлены. Интеграционная проверка создаёт временную локальную D1 и запускает собственный Worker; рабочая база не используется. Учётные данные тестов генерируются в памяти.

## Сохранение данных

Каждая запись передаёт версию загруженного состояния. Сервер атомарно отклоняет устаревшую запись с HTTP 409. Независимые изменения разных записей объединяются; при изменении одной записи с двух устройств пользователь выбирает версию. При выборе сохраняется локальная резервная копия.

Неотправленные изменения записываются в localStorage данного браузера без паролей и восстанавливаются после повторного входа. При закрытии вкладки с несохранёнными правками показывается предупреждение. После восстановления связи очередь повторяет отправку. Очистка данных браузера удаляет и локальные черновики: при проблемах с сетью дождитесь отметки успешного сохранения или выгрузите резервную копию.

Текущий продавец и режим интерфейса хранятся на конкретном устройстве и не переключают другие устройства. Выбор имени продавца является отметкой автора операции, а не отдельной учётной записью с персональными правами.

Импорт сначала проверяет структуру файла и создаёт локальную копию исходных данных, затем записывает замену с паролем действий. При ошибке записи текущие данные остаются доступны. Пароли не включаются в экспорт или черновики. Все вошедшие пользователи имеют доступ к общим рабочим данным; пароль действий ограничивает удаление и замену на сервере.

При обычном открытии сайта запрашивается только пароль входа. Кнопка «Импортировать данные» сначала проверяет пароль действий, затем открывает выбор файла; подтверждение импорта использует это разрешение без повторного запроса. Отмена пароля не открывает выбор файла. Фоновая синхронизация сама окно пароля действий не показывает: если для сохранения требуется такое разрешение, черновик сохраняется на устройстве до нажатия «Подтвердить сохранение».

## Протокол API

- GET /api/state: `{state, updatedAt}`, требуется заголовок X-Garage-Password.
- PUT /api/state: `{state, baseUpdatedAt}`; для первой записи baseUpdatedAt равен null.
- Если версия отсутствует — HTTP 428; при конфликте — HTTP 409 с последним state/updatedAt.
- Удаление существующих записей или ключей, а также `operation: "replace"` дополнительно требуют X-Garage-Action-Password. Перенос заказа в архив сохраняет запись и не считается удалением.
- Настройки устройства исключаются из общего состояния.

## Обновление рабочего сайта

`npm run deploy` публикует Worker `garage` и его статические файлы вместе. Его адрес — `https://garage.livea0624.workers.dev/`. Привязка `GARAGE_DB` указывает на существующую базу `garage-cloud-db`; её имя подтверждено в настройках рабочего сайта. Перед первой публикацией из нового аккаунта проверьте, что UUID базы в `wrangler.jsonc` относится к ней. Для публикации требуется доступ Cloudflare к этому Worker и базе.

`npm run d1:init` — отдельная команда для УДАЛЁННОЙ D1. Не используйте её вместо локальной инициализации.

Перед первым обновлением сохраните резервную копию и завершите редактирование в старых открытых вкладках. Обновите страницы на остальных устройствах: старый клиент без версии состояния получит HTTP 428 и не сможет перезаписать данные новым протоколом. Существующая схема D1 совместима, очистка базы и повторное создание паролей не нужны.
